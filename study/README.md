# 从头实现 MiniMind

第一轮的目标是从随机权重开始，用自己写的模型学会几条短句，保存权重，在新进程里重新加载并续写；最后用同一个模型做聊天监督微调（SFT）。学习版放在 `study/`，复用仓库分词器和 PyTorch。下面的接口是练习目标，可在实现时调整。

从仓库根目录开始。云环境中可先运行 `source /workspace/minimind-env/activate.sh`。前四个阶段用 CPU、float32、隐藏维度 64、1～2 层和不超过 128 个 token 的序列。下文用 B 表示批大小、T 表示序列长度、D 表示隐藏维度、V 表示词表大小。源码对照基于提交 `cc9629e5f464`。

## 1. 让两个句子变成训练样本

**动手**　在 `study/data.py` 写 `encode_pretrain(text, tokenizer, max_length) → (input_ids, labels)`。正文最多取 `max_length - 2` 个 token，首尾加 BOS 和 EOS，再向右补 PAD。两个返回值都是长度 T 的整数张量。预训练标签复制输入，补齐位置填 `-100`。先用两条内存中的文本，等训练循环需要批数据时再接入 JSONL。对照 `PretrainDataset.__getitem__`。[预训练数据实现](../dataset/lm_dataset.py)

**验收**　用本地分词器编码下表中的文本，取 T = 6。最后一列是计算损失时与前五个位置的输出配对的目标。先用纸笔填这一列，再与代码输出核对。[分词器配置](../model/tokenizer_config.json)

| 文本 | input_ids | labels | 下一 token 的目标 |
| --- | --- | --- | --- |
| 你好 | 1, 1968, 2, 0, 0, 0 | 1, 1968, 2, -100, -100, -100 | 1968, 2, -100, -100, -100 |
| 你好，世界 | 1, 1968, 294, 1950, 2, 0 | 1, 1968, 294, 1950, 2, -100 | 1968, 294, 1950, 2, -100 |

两行合起来应有 **6 个有效预测目标**。解释为什么第一行中“你好”要预测 EOS，而第二行同一个位置要预测逗号。再把第二行的 T 改成 4，检查截断后 EOS 仍在末尾。

## 2. 让一次预测产生梯度

**动手**　在 `study/model.py` 写一个只含 Embedding 和线性输出层的基线。让 `forward(input_ids, labels=None)` 产生形状为 `[B,T,V]` 的 logits；给定标签时再返回标量 loss。沿用原实现的分工，只在模型里把 `logits[:, :-1, :]` 与 `labels[:, 1:]` 配对，对有效位置取平均交叉熵。对照 `MiniMindForCausalLM.forward`。[语言模型输出层](../model/model_minimind.py)

**验收**　给阶段 1 的两条样本传入全零 logits，各位置的预测概率都应是 `1/V`，所以平均 loss 应接近 `ln(6400) ≈ 8.764`。单独改变一个目标为 `-100` 的位置所对应的 logits，loss 应保持一致。然后换回模型输出，完成一次反向传播和参数更新，检查输出层权重确实改变。

## 3. 让每个位置读到前文

**动手**　在 `study/model.py` 先写单头注意力，打印一个 4×4 的注意力矩阵。按头维度的平方根缩放 QK 分数，遮住对角线上方的位置，沿最后一维做 softmax，再加权求和 V（此处指 value 向量）。扩展到多头，先让 Q、K、V 的头数相同。最后组装一个块，两条残差分支各自先做 RMSNorm，分别接注意力与门控前馈层 `down(silu(gate(x)) * up(x))`。对照 `Attention` 的显式计算分支、`FeedForward` 和 `MiniMindBlock`。[Transformer 块](../model/model_minimind.py)

**验收**　关闭 dropout，检查每一行可见位置的注意力权重之和约为 1，未来位置的权重为 0。两段输入共享前缀，只替换最后一个 token，前缀的输出应逐位置相同。再改变首个 token，观察后面位置的输出是否随上下文改变。

## 4. 拼出 MiniMind 的稠密模型

**动手**　一次加入一项，并保留阶段 3 的因果性检查。先在投影后的 Q、K 上依次应用每个头的 RMSNorm 和 RoPE 旋转位置编码。再加入分组查询注意力（GQA），设 8 个查询头、4 个 KV 头，每两个查询头共享一组 K、V。最后堆叠两层，加入最终 RMSNorm，让词嵌入与输出层共享权重。将词表大小、维度、头数和层数放入配置。对照 `apply_rotary_pos_emb`、`repeat_kv`、`MiniMindModel` 和 `MiniMindForCausalLM`。[模型组装与配置](../model/model_minimind.py)

**验收**　D = 64 时每个查询头维度为 8。用同一组 Q、K 比较旋转前后，位置 0 的值应相同，其他位置的向量范数应在浮点误差内保持一致。打印 GQA 展开前后的 K 形状并检查共享关系。用两个长度为 6 的样本跑完整模型，输出应为 `[2,6,6400]`，loss 与梯度应为有限值，两处共享权重应指向同一个参数。

## 5. 训练、保存，再接着训练

**动手**　在 `study/train.py` 把数据加载、前向、反向、AdamW 更新和清空梯度连起来。先固定数据顺序和学习率，选两条容易记住的短句，例如“甲的颜色是红色。”和“乙的颜色是蓝色。”。记录不同前缀的正确下一 token 及其预测概率。学会这些样本后，再加梯度累积、裁剪和学习率调度。对照 `train_epoch`、`get_lr` 和 `lm_checkpoint`。[预训练入口](../trainer/train_pretrain.py) · [训练工具](../trainer/trainer_utils.py)

**验收**　检查模型能为两个不同前缀选出各自正确的颜色 token。保存模型配置和权重，在新进程里重建模型，相同输入在评估模式下的 logits 应一致。然后在优化器更新边界保存模型、优化器和步数，在固定批次顺序、关闭 dropout 的条件下，对比连续训练三步与训练两步后恢复再走一步的参数。若加入调度器，同时恢复其进度。

## 6. 用训练好的权重续写

**动手**　在 `study/generate.py` 写 `generate(input_ids, max_new_tokens, eos_id)`。先支持单条提示词，每次取最后一个位置的 logits，选概率最大的 token，追加到输入，直到 EOS 或长度上限。随后加入温度、top-k 和 top-p 采样。原项目的 CLI 负责构造提示词和解码，逐 token 循环在模型的 `generate` 方法中。[CLI](../eval_llm.py) · [生成循环](../model/model_minimind.py)

**验收**　用阶段 5 保存的权重和两个前缀做贪心续写，比较新增后缀与训练短句。给采样器一组有唯一最大值的分数，`top_k=1` 的结果应与贪心选择相同。分别构造首步就选中 EOS 和始终未选中 EOS 的情形，核对新增 token 数量。选做 KV cache 时，每一步都用相同前缀比较缓存与全量重算的最后一位 logits，再比较耗时。

## 7. 让同一个模型学习对话

**动手**　在 `study/data.py` 增加聊天编码，在 `study/train.py` 加载阶段 5 的权重做全参数微调。先用一条固定的两轮对话，借助本地 `apply_chat_template` 看清角色边界。自己构造监督标签，保留每轮助手正文及回复结束标记（原实现还包括其后的换行），其余位置填 `-100`。损失继续使用阶段 2 的移位方式。对照 `SFTDataset.create_chat_prompt`、`generate_labels` 和 `train_full_sft.py`。[聊天数据](../dataset/lm_dataset.py) · [微调入口](../trainer/train_full_sft.py)

**验收**　把两个助手回复各自参与损失的 token 单独解码，逐段与原文核对，同时检查用户文本、角色前缀和 PAD 的标签。若截断后没有有效目标，跳过该样本。对少量问答训练后，在新进程里只给用户问题和助手起始标记，用阶段 6 的贪心生成核对答案与 EOS。
